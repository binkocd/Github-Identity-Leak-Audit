# GitHub Identity Security Auditor

## 🛡️ Overview
The **GitHub Identity Security Auditor** is an automated tool designed to scan all repositories owned by an authenticated GitHub user for identity leaks in the Git commit history. 

In environments where separating personal and professional identities is critical, misconfigured local Git environments can easily leak real names or personal email addresses into public repositories. This tool acts as a safeguard, scanning your entire footprint to ensure all commits conform to a strictly authorized Git identity.

Any commit matching your specified unauthorized names or emails—or failing to use the correct GitHub `noreply` email—will be flagged.

## 🚀 Setup & Installation

### Step 1: Repository Setup (Creating your HOME_REPO)

Because this tool creates GitHub Issues containing details about your leaked identities, **your repository must be strictly private**. Do not use a standard fork, as GitHub forces forks of public repositories to remain public.

1. Click the green **Use this template** button at the top of this repository.
2. Select **Create a new repository**.
3. Name your repository (e.g., `github-identity-auditor`).
4. **CRITICAL:** Set the visibility to **Private**.
5. Click **Create repository**.
6. Clone your newly created private repository to your local machine to continue setup.

### Step 2: Generate a Personal Access Token (PAT)
The script requires a token to fetch your repositories, clone them, and manage the reporting issue.
1. Navigate to **GitHub Settings** > **Developer settings** > **Personal access tokens** > **Fine-grained tokens**.
2. Click **Generate new token**.
3. Under **Repository access**, select **All repositories**.
4. Grant the following **Repository permissions**:
   * **Contents:** `Read-only`
   * **Issues:** `Read and Write`
   * **Metadata:** `Read-only`
5. Generate and copy the token.

### Step 3: Configure Repository Secrets & Variables
You must define your identity rules using GitHub Actions Secrets and Variables.

1. Navigate to your `HOME_REPO` on GitHub.
2. Go to **Settings** > **Secrets and variables** > **Actions**.
3. Under the **Secrets** tab, click **New repository secret**:
   * Name: `GH_PAT_AUDIT`
   * Value: *(Paste your Fine-Grained PAT here)*
4. Under the **Variables** tab, click **New repository variable** to configure your rules:
   * `AUTHORIZED_NAME` : Your authorized GitHub handle (e.g., `johndoe`).
   * `UNAUTHORIZED_NAMES` : A comma-separated list of names to flag (e.g., `John Doe,Johnny Doe`).
   * `UNAUTHORIZED_EMAILS` : A comma-separated list of emails to flag (e.g., `john@personal.com,work@company.com`).

*(Note: The script will automatically flag any commits made under your `AUTHORIZED_NAME` that do not use the official GitHub `ID+username@users.noreply.github.com` privacy format).*

### Step 4: Run the Audit
1. Navigate to the **Actions** tab in your repository.
2. Select **Security Audit - Identity Leaks** from the sidebar.
3. Click **Run workflow**.
4. Check the **Issues** tab for your `[SECURITY-AUDIT]` report once the run completes!

## 🧹 Remediation: Fixing Identity Leaks

If the auditor flags violations, you must rewrite the Git history to correct the author info using git-filter-repo.

⚠️ Warning: Rewriting history changes commit hashes. Coordinate with collaborators before force-pushing.
### Step 1: Install git-filter-repo
```bash
pip install git-filter-repo
```

### Step 2: Create a .mailmap file

Create mailmap.txt to map bad identities to the correct one. <br>
Format: Correct Name <correct@email.com> Bad Name <bad@email.com>
```
John Doe <123456+johndoe@users.noreply.github.com> Johnny <john.personal@gmail.com>
John Doe <123456+johndoe@users.noreply.github.com> John Doe <{ID}+{username}@users.noreply.github.com>
```

### Step 3: Rewrite and Push

## (AUTOMATED) Run this for every flagged repository:

The `remediate_all.py` script automates the cleanup of your Git history across all flagged repositories. It operates safely by creating local `.bundle` backups and executing `git-filter-repo` inside an isolated, temporary Python virtual environment.

**Step 1: Prepare Your Files**
Ensure the following two files are in the same directory as the script:
1. `audit_results.csv`: The output file generated by the audit tool.
2. `mailmap.txt`: Your identity mapping file (Format: `Correct Name <correct@email> Bad Name <bad@email>`).

**Step 2: Run the Script**
Execute the script using Python 3, passing your GitHub username and the required file paths:

```bash
python remediate_all.py -u YOUR_GITHUB_USERNAME -c audit_results.csv -m mailmap.txt
```

## (MANUAL) Run this for every flagged repository:

### 1. Clone a fresh, bare copy
```bash
git clone --bare https://github.com/YOUR-USERNAME/YOUR-REPO.git
cd YOUR-REPO.git
```

###  2. Run the filter
```bash
git filter-repo --mailmap /path/to/your/mailmap.txt
```

###  3. Force push back to GitHub
```bash
git push --all --force
git push --tags --force
```

###  4. Clean up
```bash
cd ..
rm -rf YOUR-REPO.git

```

## 💻 Local Testing
To run the tool against a local repository on your machine before pushing to GitHub, use the `--local` flag. You must export your variables to your local shell first.

```bash
export AUTHORIZED_NAME="johndoe"
export UNAUTHORIZED_NAMES="John Doe"
export UNAUTHORIZED_EMAILS="john@personal.com"

python audit_github.py --local
```
